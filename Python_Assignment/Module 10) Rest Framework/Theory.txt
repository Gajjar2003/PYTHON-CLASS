    1. Introduction to APIs

        1.What is an API (Application Programming Interface)?

                An API (Application Programming Interface) is basically a messenger that lets different software applications talk to each other 🤝

                Instead of apps directly accessing each other’s code or database, they use an API to request and exchange data or services in a safe, structured way.

                Think of it like this 🍽️

                You’re at a restaurant:

                You (client/app) → place an order

                Waiter (API) → takes your order

                Kitchen (server/system) → prepares the food

                Waiter (API) → brings the food back

                You never go into the kitchen—you just interact through the waiter. That’s exactly how an API works.

                What does an API do?

                An API:

                Defines what requests are allowed

                Specifies how to make those requests

                Returns responses in a fixed format (usually JSON or XML)

                Simple real-world examples 🌍

                A weather app uses an API to get weather data from a server

                Google Maps API shows maps inside other apps

                Payment gateways (Razorpay, Stripe) use APIs to process payments

                Login with Google/Facebook uses APIs for authentication

        2.Types of APIs: REST, SOAP.

                | Feature     | REST                | SOAP               |
                | ----------- | ------------------- | ------------------ |
                | Protocol    | Architectural style | Protocol           |
                | Data format | JSON, XML           | XML only           |
                | Speed       | Fast                | Slow               |
                | Complexity  | Simple              | Complex            |
                | Popularity  | Very high           | Declining          |
                | Best for    | Web & mobile apps   | Enterprise systems |

        3.Why are APIs important in web development?

        🔑 Why APIs are Important in Web Development
            1️⃣ Connect Frontend and Backend

            APIs act as a bridge between:

            Frontend (HTML, CSS, JS, React, etc.)

            Backend (Django, Node, Java, etc.)

            The frontend doesn’t directly touch the database—it calls an API instead.

            2️⃣ Enable Data Sharing

            APIs allow different systems to share data securely:

            Website ↔ Mobile App

            App ↔ Third-party service

            Server ↔ Server

            Example:
            An e-commerce site using a payment gateway API.

            3️⃣ Improve Security 🔐

            Database is never exposed directly

            APIs control what data is accessible

            Authentication (tokens, API keys, JWT)

            4️⃣ Faster Development ⏱️

            Developers can:

            Reuse existing APIs

            Work in parallel (frontend & backend teams)

            Integrate ready-made services (maps, payments, emails)

            5️⃣ Support Multiple Platforms 📱💻

            One API can serve:

            Website

            Mobile app

            Desktop app

            Same backend, multiple clients.

            6️⃣ Scalability & Maintenance

            Easier to update or replace parts of the system

            Changes in backend don’t break frontend if API stays same

            Helps in microservices architecture

            7️⃣ Third-Party Integrations 🌍

            APIs let you add powerful features without building everything:

            Google Login

            Stripe / Razorpay payments

            SMS & Email services

            Weather, Maps, Analytics

        3.Using serializers in Django REST Framework (DRF).


                What is a Serializer in DRF?

                A serializer:

                Converts Django model objects → JSON (serialization)

                Converts JSON → Django objects (deserialization)

                Validates data before saving to the database

                1️⃣ Install & Setup DRF
                pip install djangorestframework


                Add to settings.py:

                INSTALLED_APPS = [
                    ...
                    'rest_framework',
                ]

                2️⃣ Create a Model
                from django.db import models

                class Product(models.Model):
                    name = models.CharField(max_length=100)
                    price = models.IntegerField()
                    stock = models.IntegerField()

                    def __str__(self):
                        return self.name

                3️⃣ Create a Serializer
                ✔ ModelSerializer (Most Used)
                from rest_framework import serializers
                from .models import Product

                class ProductSerializer(serializers.ModelSerializer):
                    class Meta:
                        model = Product
                        fields = '__all__'


                DRF automatically creates fields and validation rules from the model.

                4️⃣ Use Serializer in Views
                GET (Read data)
                from rest_framework.response import Response
                from rest_framework.decorators import api_view
                from .models import Product
                from .serializers import ProductSerializer

                @api_view(['GET'])
                def product_list(request):
                    products = Product.objects.all()
                    serializer = ProductSerializer(products, many=True)
                    return Response(serializer.data)

                POST (Create data)
                @api_view(['POST'])
                def product_create(request):
                    serializer = ProductSerializer(data=request.data)
                    if serializer.is_valid():
                        serializer.save()
                        return Response(serializer.data, status=201)
                    return Response(serializer.errors, status=400)

                5️⃣ Validation in Serializer
                Field-level validation
                def validate_price(self, value):
                    if value <= 0:
                        raise serializers.ValidationError("Price must be greater than zero")
                    return value

                Object-level validation
                def validate(self, data):
                    if data['stock'] < 0:
                        raise serializers.ValidationError("Stock cannot be negative")
                    return data

        4. Requests and Responses in Django REST Framework

            1.HTTP request methods (GET, POST, PUT, DELETE).

            GET — Retrieve Data

            Purpose: Fetch data from the server

            Does not change data

            Safe & read-only

            Example:

            GET /api/products/
            GET /api/products/1/


            DRF View Example:

            @api_view(['GET'])
            def product_list(request):
                products = Product.objects.all()
                serializer = ProductSerializer(products, many=True)
                return Response(serializer.data)

            2️⃣ POST — Create New Data

            Purpose: Send data to create a new resource

            Data is sent in request body

            Changes server data

            Example:

            POST /api/products/


            JSON Body:

            {
            "name": "Shoes",
            "price": 1200
            }


            DRF Example:

            @api_view(['POST'])
            def product_create(request):
                serializer = ProductSerializer(data=request.data)
                if serializer.is_valid():
                    serializer.save()
                    return Response(serializer.data, status=201)

            3️⃣ PUT — Update Entire Resource

            Purpose: Update all fields of an existing resource

            Replaces old data completely

            Example:

            PUT /api/products/1/


            DRF Example:

            product = Product.objects.get(id=1)
            serializer = ProductSerializer(product, data=request.data)
            if serializer.is_valid():
                serializer.save()


            ⚠️ All fields must be provided.

            4️⃣ DELETE — Remove Data

            Purpose: Delete a resource

            Permanently removes data

            Example:

            DELETE /api/products/1/


            DRF Example:

            product = Product.objects.get(id=1)
            product.delete()
            return Response(status=204)
    
        2.Sending and receiving responsesin DRF.

                📥 Receiving Requests in DRF

                Client (frontend / Postman / mobile app) sends data to your API.

                Access request data
                request.data


                Works for POST, PUT, PATCH

                Automatically parses JSON, form data, etc.

                Example (POST request)
                @api_view(['POST'])
                def create_product(request):
                    serializer = ProductSerializer(data=request.data)
                    if serializer.is_valid():
                        serializer.save()
                        return Response(serializer.data, status=201)
                    return Response(serializer.errors, status=400)

                📤 Sending Responses in DRF

                DRF uses the Response class instead of Django’s HttpResponse.

                from rest_framework.response import Response

                Basic Response
                return Response({"message": "Product created"})

                Response with serialized data
                return Response(serializer.data)

                Response with status code
                from rest_framework import status

                return Response(serializer.data, status=status.HTTP_201_CREATED)

    5. Views in Django REST Framework

        1.Understanding views in DRF: Function-based views vs Class-based views.

            Function-Based Views (FBVs)

            These are simple Python functions decorated with DRF helpers.

            Example (FBV)
            from rest_framework.decorators import api_view
            from rest_framework.response import Response

            @api_view(['GET', 'POST'])
            def product_list(request):
                if request.method == 'GET':
                    products = Product.objects.all()
                    serializer = ProductSerializer(products, many=True)
                    return Response(serializer.data)

                elif request.method == 'POST':
                    serializer = ProductSerializer(data=request.data)
                    if serializer.is_valid():
                        serializer.save()
                        return Response(serializer.data, status=201)
                    return Response(serializer.errors, status=400)


            Class-Based Views (CBVs)

            These use classes instead of functions and map HTTP methods to class methods.

            Example (APIView)
            from rest_framework.views import APIView
            from rest_framework.response import Response

            class ProductList(APIView):

                def get(self, request):
                    products = Product.objects.all()
                    serializer = ProductSerializer(products, many=True)
                    return Response(serializer.data)

                def post(self, request):
                    serializer = ProductSerializer(data=request.data)
                    if serializer.is_valid():
                        serializer.save()
                        return Response(serializer.data, status=201)
                    return Response(serializer.errors, status=400)

        6. URL Routing in Django REST Framework

            1.Defining URLs and linking them to views.

                 Defining URLs and Linking Them to Views (Django & DRF)

                URLs tell Django which view should handle a request. In DRF, URL routing connects an API endpoint to a view or ViewSet.

                Let’s break it down clearly 👇

                1️⃣ Basic URL Structure in Django

                URLs are defined in urls.py.

                from django.urls import path
                from . import views

                urlpatterns = [
                    path('products/', views.product_list),
                ]


                ➡️ When someone visits /products/, Django calls product_list view.

                2️⃣ Linking URLs to Function-Based Views (FBVs)
                View
                @api_view(['GET'])
                def product_list(request):
                    ...

                URL
                from django.urls import path
                from .views import product_list

                urlpatterns = [
                    path('api/products/', product_list, name='product-list'),
                ]

                3️⃣ Linking URLs to Class-Based Views (CBVs)
                View
                class ProductList(APIView):
                    def get(self, request):
                        ...

                URL
                from django.urls import path
                from .views import ProductList

                urlpatterns = [
                    path('api/products/', ProductList.as_view(), name='product-list'),
                ]


                ⚠️ .as_view() is mandatory for CBVs.

                4️⃣ URLs with Parameters (Dynamic URLs)
                path('api/products/<int:id>/', views.product_detail)


                Usage:

                GET /api/products/1/


                CBV:

                path('api/products/<int:pk>/', ProductDetail.as_view())

                5️⃣ Using Generic Views (Clean & Recommended ⭐)
                from rest_framework.generics import ListCreateAPIView

                urlpatterns = [
                    path('api/products/', ProductList.as_view()),
                ]

                6️⃣ Using Routers with ViewSets (Best Practice 🚀)
                ViewSet
                from rest_framework.viewsets import ModelViewSet

                class ProductViewSet(ModelViewSet):
                    queryset = Product.objects.all()
                    serializer_class = ProductSerializer

                URLs
                from rest_framework.routers import DefaultRouter

                router = DefaultRouter()
                router.register('products', ProductViewSet)

                urlpatterns = router.urls

                 Adding Pagination to APIs (DRF) — Handling Large Data Sets

                When an API returns a lot of data, pagination helps by splitting results into smaller pages. This makes APIs faster, lighter, and scalable 🚀

                🔍 Why Pagination is Important

                Improves performance

                Reduces server load

                Faster response time

                REST_FRAMEWORK = {

        11. RESTful API Design

            1.REST principles: statelessness, resource-based URLs, and using HTTP methods for CRUD operations.


                🌐 REST Principles

                (Statelessness, Resource-Based URLs & HTTP Methods for CRUD)

                REST (Representational State Transfer) is a set of rules for designing scalable, clean APIs. These three principles are the core ones you’ll use daily 👇

                1️⃣ Statelessness

                Meaning:
                Each API request must contain all the information needed to process it.
                The server does not remember previous requests.

                Example

                ❌ Wrong idea:

                “Server remembers the user after login”

                ✅ REST way:

                Client sends token (JWT / session ID) with every request

                GET /api/orders/
                Authorization: Bearer eyJhbGciOiJIUzI1...

                Benefits

                ✔ Easy scaling
                ✔ No server-side session dependency
                ✔ Reliable & predictable APIs

                2️⃣ Resource-Based URLs

                Meaning:
                URLs should represent resources (nouns), not actions (verbs).

                Good REST URLs ✅
                /api/users/
                /api/users/1/
                /api/products/
                /api/orders/10/

                Bad URLs ❌
                /api/getUsers/
                /api/createProduct/
                /api/deleteOrder/

                Why?

                Clean & readable

                Consistent API design

                Works naturally with HTTP methods

                3️⃣ Using HTTP Methods for CRUD Operations

                Instead of verbs in URLs, REST uses HTTP methods to define actions.

                CRUD	HTTP Method	Example
                Create	POST	POST /api/products/
                Read	GET	GET /api/products/
                Read (one)	GET	GET /api/products/1/
                Update	PUT / PATCH	PUT /api/products/1/
                Delete	DELETE	DELETE /api/products/1/
                Example Flow
                POST /api/products/


                Creates a new product

                GET /api/products/5/


                Fetches product with ID 5

                🧠 Putting It All Together (DRF Example)
                class ProductViewSet(ModelViewSet):
                    queryset = Product.objects.all()
                    serializer_class = ProductSerializer


                Auto-generated REST endpoints:

                GET /products/

                POST /products/

                GET /products/{id}/

                PUT /products/{id}/

                DELETE /products/{id}/

       13. Authentication and Authorization API

            1.Difference between authentication and authorization.

            🔐 Authentication vs 🛂 Authorization
                Authentication

                👉 Who are you?

                Authentication is the process of verifying a user’s identity.

                Happens first

                Confirms username/password, OTP, token, biometrics, etc.

                Example: Logging in with email & password

                Question it answers:
                ➡️ “Are you really Jenil?”

                Examples:

                Login with username & password

                OTP verification

                Google / Facebook login

                JWT token validation

                Authorization

                👉 What are you allowed to do?

                Authorization is the process of checking permissions or access rights.

                Happens after authentication

                Controls access to resources/features

                Based on roles, permissions, policies

                Question it answers:

                3️⃣ Create Token Automatically When User Is Created

                Create signals.py in your app:

                from django.conf import settings
                from django.dispatch import receiver
                from django.db.models.signals import post_save
                from rest_framework.authtoken.models import Token

                @receiver(post_save, sender=settings.AUTH_USER_MODEL)
                def create_auth_token(sender, instance=None, created=False, **kwargs):
                    if created:
                        Token.objects.create(user=instance)

                from rest_framework.decorators import api_view, permission_classes

                What is REST Countries API?

                REST Countries API is a public REST API that provides information about countries such as:

                Country name

                Currency

                Flag URL

                📌 No authentication required (totally free).

                Purpose	Endpoint
                All countries	/all
                By name	/name/{country}
                By country code	/alpha/{code}
                By region	/region/{region}
                🔍 Retrieve Country Data by Name
                Example Request
                https://restcountries.com/v3.1/name/india

                📥 Sample JSON Response (Simplified)
                [
                {
                    "name": {
                    "common": "India"
                    },
                    "capital": ["New Delhi"],
                    "region": "Asia",
                    "population": 1400000000,
                    "flags": {
                    "png": "https://flagcdn.com/w320/in.png"
                    }
                }
                ]

                🧠 Important Fields Explained
                Field	Meaning
                name.common	Country name
                capital[0]	Capital
                region	Continent
                population	Population
                flags.png	Flag image URL
                🐍 Python Example (Fetch Country Data)
                import requests

                country = "india"
                url = f"https://restcountries.com/v3.1/name/{country}"

                response = requests.get(url)
                data = response.json()

                country_data = data[0]

                print("Country:", country_data["name"]["common"])
                print("Capital:", country_data["capital"][0])
                print("Region:", country_data["region"])
                print("Population:", country_data["population"])

                🌐 Django View Example
                import requests
                from django.http import JsonResponse

                def country_info(request):
                    name = request.GET.get("country", "india")
                    url = f"https://restcountries.com/v3.1/name/{name}"

                    response = requests.get(url)
                    data = response.json()

                    if response.status_code == 200:
                        country = data[0]
                        return JsonResponse({
                            "name": country["name"]["common"],
                            "capital": country["capital"][0],
                            "population": country["population"],
                            "region": country["region"]
                        })

                    return JsonResponse({"error": "Country not found"})

                    pip install twilio

                    ✉️ Sending SMS Using Twilio
                    Basic Python Example
                    from twilio.rest import Client

                    account_sid = "YOUR_ACCOUNT_SID"
                    auth_token = "YOUR_AUTH_TOKEN"

                    client = Client(account_sid, auth_token)

                    message = client.messages.create(
                        body="Hello from Twilio 👋",
                        from_="+1234567890",   # Twilio number
                        to="+919876543210"     # User number
                    )

                    print(message.sid)

                    🔐 Sending OTP Using Twilio
                    Generate OTP
                    import random

                    otp = random.randint(100000, 999999)

                    Send OTP SMS
                    message = client.messages.create(
                        body=f"Your OTP is {otp}. Do not share it.",
                        from_="+1234567890",
                        to="+919876543210"
                    )

                    🌐 Django Example (OTP Send View)
                    import random
                    from django.http import JsonResponse
                    from twilio.rest import Client

                    def send_otp(request):
                        phone = request.GET.get("phone")
                        otp = random.randint(100000, 999999)

                        client = Client(
                            "ACCOUNT_SID",
                            "AUTH_TOKEN"
                        )

                        client.messages.create(
                            body=f"Your OTP is {otp}",
                            from_="+1234567890",
                            to=phone
                        )

                        # Save OTP in session / DB
                        request.session["otp"] = otp

                        return JsonResponse({"message": "OTP sent successfully"})

                    ✅ OTP Verification Logic
                    def verify_otp(request):
                        user_otp = request.GET.get("otp")

                        if str(request.session.get("otp")) == user_otp:
                            return JsonResponse({"message": "OTP verified"})
                        
                        return JsonResponse({"error": "Invalid OTP"})
